# pyanypia Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pure-Python, penny-exact port of SSA's AnyPIA Detailed Calculator engine (2026 TR version) published as a public GitHub package, validated differentially against the compiled C++ oracle.

**Architecture:** Pythonic re-architecture (immutable inputs, pure engine functions, declarative reform layer) with arithmetic transliterated faithfully from the C++ — see the approved spec at `docs/superpowers/specs/2026-08-22-pyanypia-design.md`. The compiled `anypiab` (plus a JSON-instrumented variant and a params-dump tool) is the ground truth at every step.

**Tech Stack:** Python ≥3.11 stdlib-only runtime; pytest/ruff/mypy dev; clang++ + Boost headers for the oracle; GitHub Actions CI.

**Ground rules for every task:**
- The C++ file named in a task is the *behavioral spec*. Read it fully before porting. Preserve operation order and rounding inside each computation; re-architect only module boundaries.
- All money math goes through `pyanypia/rounding.py` helpers. Never bare `round()` on money. No numpy in the engine.
- Every port task ends with its oracle-differential or unit tests passing, `ruff check` clean, and a commit. Push to GitHub at least at the end of every phase.
- Update the checkboxes in THIS file as tasks complete (this file is the durable progress state across context windows).
- C++ source root (read-only): `~/Desktop/Benefit calculator source code/` — vendored copy inside repo at `oracle/vendor/` (equally authoritative, use it once vendored).
